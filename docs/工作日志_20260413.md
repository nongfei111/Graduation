## 三、系统架构

### 3.1 整体架构

```
┌─────────────┐
│   手机 APP   │  ← 用户远程查看/控制
└──────┬──────┘
       │ HTTP/Internet
       ▼
┌─────────────┐
│  云服务器    │  ← API 服务 + 数据存储
│ 8.134.196.56│
└──────┬──────┘
       │ HTTP/Internet
       ▼
┌─────────────┐
│  设备端      │  ← 人脸识别 + 执行命令
│  (树莓派)    │
└─────────────┘
```

### 3.2 数据流

#### 远程开门流程:
```
手机 APP → 云服务器 → 设备端
  ↓          ↓          ↓
开门命令  保存命令   轮询获取
          ↓          ↓
       数据库      执行命令
                    ↓
                 上报结果
```

#### 访客上传流程:
```
设备端 → 云服务器 → 手机 APP
  ↓          ↓          ↓
抓拍照片  存储记录   推送通知
          ↓          ↓
       数据库    刷新列表
```

## 八、技术要点

### 8.1 心跳机制

设备端每 30 秒发送一次心跳到服务器：
- 维持设备在线状态
- 获取待执行的远程命令
- 检测网络连通性

### 8.2 Token 认证

使用 JWT 进行身份认证：
- Token 有效期：24 小时
- 刷新 Token 有效期：30 天
- 所有控制接口需要 Token

### 8.3 命令轮询

设备端通过心跳轮询获取远程命令：
- 服务器将命令存储在数据库
- 设备端心跳时返回待执行命令
- 命令执行后上报结果

### 8.4 数据安全

- 密码使用 bcrypt 加密
- Token 使用 JWT 签名
- 建议生产环境启用 HTTPS
