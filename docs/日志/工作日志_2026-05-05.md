## 关键问题与结论

- App 远程控制失败显示 `doorbell_001`：
  - 根因：App 设备状态接口解析失败导致 device_id 没更新，仍用默认值。
  - 触发点：`/api/device/status` 返回 `is_online=0/1`（数字），App 期望 boolean，Gson 抛 `Expected a boolean but was NUMBER`。
- 访客列表越权：
  - 根因：`/api/visitor/list` 在“当前用户无绑定设备”时未加 device_id 过滤，等价返回全表。
- 远程开锁“命令已发送但电机不转”：
  - 根因：树莓派设备未及时心跳在线，云端 remote_commands 长时间 pending；恢复在线后即可执行。
  - 另一个阻断点：远程开锁处理里调用了不存在的 `display.show_message` 导致命令执行上报失败（已修）。
- 远程抓拍失败 `No module named 'onnxruntime'`：
  - 根因：旧抓拍实现依赖 `src.core.camera`（引入 onnxruntime），树莓派环境缺该依赖。
- 同一秒多条访客上传：
  - 根因：本地 `data/visitors.json` 队列积压，DataSync 一次同步批量上传冲刷云端。
  - 现场数据：积压 267 条。
